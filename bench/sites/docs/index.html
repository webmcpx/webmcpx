Orbit CLI reference

Orbit builds, deploys and runs web applications. This page documents every command of the orbit CLI, version 3.8. Install it with curl -fsSL https://get.orbit.example | sh or brew install orbit.

Commands

Every command accepts --help, --json for machine-readable output and --quiet to print only errors.

orbit init

Create an orbit.toml in the current directory and link it to a project.

Flag or subcommandDefaultDescription
--namedirectory nameProject name shown in the dashboard.
--regioneu-westDefault region for new environments.
--templatenoneStart from a template: static, node or rust.

Example:

orbit init --name shop --region us-east

orbit build

Build the project into an immutable artifact. Builds run in a clean container and are cached by the hash of your lockfiles.

Flag or subcommandDefaultDescription
--timeout300 secondsAbort the build after this long.
--no-cacheoffIgnore cached layers.
--targetreleaseBuild profile: release or debug.
--arg KEY=VALUEnonePass a build argument. Repeatable.

Example:

orbit build --target debug --arg API_URL=https://api.example.com

orbit deploy

Upload the latest artifact and roll it out to an environment. Traffic shifts to the new release once every instance passes its health check.

Flag or subcommandDefaultDescription
--envstagingEnvironment to deploy to.
--timeout90 secondsHow long to wait for health checks before the deploy fails and traffic stays on the previous release.
--strategyrollingrolling, blue-green or canary.
--canary-percent10Share of traffic for a canary release.
--messagenoneA note stored with the release.

Example:

orbit deploy --env production --timeout 180 --strategy blue-green

orbit rollback

Move traffic back to an earlier release of the same environment. No rebuild happens: the old artifact is reused.

Flag or subcommandDefaultDescription
--envstagingEnvironment to roll back.
--toprevious releaseRelease id to return to, as shown by orbit releases.

Example:

orbit rollback --env production --to r-2041

orbit releases

List the releases of an environment, newest first, with their id, author, message and status.

Flag or subcommandDefaultDescription
--envstagingEnvironment to list.
--limit20How many releases to show.

Example:

orbit releases --env production --limit 5

orbit logs

Stream logs from every instance of an environment.

Flag or subcommandDefaultDescription
--envstagingEnvironment to read.
--since15mStart this far back, e.g. 2h.
--followoffKeep streaming new lines.
--grepnoneOnly lines matching a regular expression.

Example:

orbit logs --env production --since 1h --grep timeout

orbit test

Run the project's test command in the same container image as the build.

Flag or subcommandDefaultDescription
--timeout120 secondsAbort the test run after this long.
--shard1/1Run one shard of the suite, e.g. 2/4.

Example:

orbit test --shard 1/3

orbit env

Create, list and delete environments.

Flag or subcommandDefaultDescription
create NAME—Create an environment.
list—List environments and their current release.
delete NAME—Delete an environment and its releases. Asks for confirmation.

Example:

orbit env create preview-42

orbit secrets

Manage encrypted secrets. Secrets are injected as environment variables at runtime and never appear in build logs.

Flag or subcommandDefaultDescription
set KEY VALUE—Create or replace a secret.
unset KEY—Remove a secret.
list—List secret names (never values).
--envall environmentsLimit to one environment.

Example:

orbit secrets set STRIPE_KEY sk_live_... --env production

orbit domains

Attach custom domains. Orbit provisions TLS certificates automatically once DNS points to your environment.

Flag or subcommandDefaultDescription
add DOMAIN—Attach a domain.
remove DOMAIN—Detach a domain.
verify DOMAIN—Check DNS and certificate status.

Example:

orbit domains add shop.example.com --env production

orbit scale

Change the number and size of instances.

Flag or subcommandDefaultDescription
--envstagingEnvironment to scale.
--instances2Instance count, 1 to 50.
--sizesmallsmall (0.5 vCPU, 512 MB), medium (1 vCPU, 2 GB) or large (4 vCPU, 8 GB).

Example:

orbit scale --env production --instances 6 --size medium

orbit login

Authenticate this machine. Opens a browser window; on headless machines, prints a one-time code instead.

Flag or subcommandDefaultDescription
--tokennoneUse an access token instead of the browser flow (for CI).

Example:

orbit login --token $ORBIT_TOKEN

Configuration file

Orbit reads orbit.toml from the current directory or the nearest parent directory. Keys use dotted names below; in the file they live under [build], [deploy] and [runtime] tables.

KeyTypeDefaultDescription
projectstringrequiredProject name.
regionstring"eu-west"Default region.
build.commandstringauto-detectedCommand that produces the artifact.
build.outputpath"dist"Directory packaged as the artifact.
deploy.health_checkpath"/healthz"Path that must return 2xx before traffic shifts.
deploy.retain_releasesinteger10How many past releases are kept for rollback. Older releases are deleted and can no longer be rolled back to.
deploy.strategystring"rolling"Default rollout strategy.
runtime.portinteger8080Port your server listens on.
runtime.max_bodysize"10 MB"Largest accepted request body.
project = "shop"
region = "us-east"

[deploy]
health_check = "/ready"
retain_releases = 25

Environment variables

VariableEffect
ORBIT_TOKENAccess token for non-interactive use. Overrides the credentials saved by orbit login.
ORBIT_HOMEDirectory for Orbit's cache and credentials. Default: ~/.orbit.
ORBIT_CONFIGPath to the project config file, instead of looking for orbit.toml in the current directory and its parents.
ORBIT_REGIONRegion used when neither a flag nor the config sets one.
ORBIT_NO_COLORDisable colored output. NO_COLOR is honored too.
ORBIT_LOGCLI log level: error, warn, info or debug.

Flags win over environment variables, which win over orbit.toml.

Exit codes

CodeMeaning
0Success.
1Generic failure; see the message.
2Invalid usage: unknown command, flag or value.
3Not authenticated. Run orbit login or set ORBIT_TOKEN.
4Quota exceeded: your plan's build minutes or instance limit is used up. Upgrade the plan or wait for the monthly reset.
5Health checks did not pass within the deploy timeout; traffic stayed on the previous release.
6Network error talking to the Orbit API. Safe to retry.
7The release or environment was not found.

Frequently asked questions

Why is my build slower than locally?

Builds start from a clean container. The first build of a branch fills the cache; later builds reuse layers unless your lockfiles change. Use --no-cache only when debugging cache problems.

Can I deploy without building?

No. Every deploy points at an artifact produced by orbit build, which keeps releases reproducible. Rollbacks are the exception: they reuse an old artifact.

How do preview environments work?

Create one per pull request with orbit env create preview-<n> and delete it when the pull request closes. Preview environments count toward your instance quota.

Where are secrets stored?

Secrets are encrypted at rest with a per-project key and decrypted only inside your instances. Orbit staff cannot read secret values.

How do I see who deployed?

Run orbit releases; every release records its author and message.

Does Orbit support WebSockets?

Yes, on all strategies. During a rolling deploy, existing connections stay on old instances until they close or 10 minutes pass.
